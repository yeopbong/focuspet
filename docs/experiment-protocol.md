# Reproducible simulation protocol

The publication verification reran five seeds: 7, 17, 27, 37, 47. The source is entirely fictional. No personal activity data was read, no population model was trained, and no real intervention was performed.

Run from the installed source checkout:

```sh
python experiments/run.py --config experiments/config.json
focuspet evaluate --config experiments/config.json
python examples/synthetic/generate_learning.py --output examples/synthetic/generated --seed 7
focuspet train --data examples/synthetic/generated/learning.json --mode synthetic-demo --output .runtime/synthetic-demo/models
focuspet calibrate --data examples/synthetic/generated/calibration.json --mode synthetic-demo --output .runtime/synthetic-demo/parameters
```

The default configuration fixes all five seeds, independent label budgets 30/60/90 and 64 objective evaluations per optimizer. It saves raw simulated records, data hashes, exact episode splits, all query decisions, per-class metrics, confusion matrices, acceptance/rejection coverage, candidate parameters, failures, timing and running best-loss curves. Machine-readable summaries live in `experiments/results/summary.json`; [the results report](../experiments/results/report.md) records actual outcomes.

## State simulation

Each seed is one fictional individual over 60 fictional days. Before creating observations, the generator samples latent task intent and engagement. Tasks include coding, low-input reading, writing, mouse-oriented design, browser activity and video. Individual speed, switching style, correlated rhythm, count noise, changed habits and test-only automation patterns affect emissions. Ground-truth labels come from the latent state, never from GenericPrior output. This deliberately creates overlap and ambiguity between different intents with similar statistics.

Six nonoverlapping feedback episodes occur daily. Each has 10-second aggregate buckets and two overlapping feature windows generated by the production FeatureBuilder. Both windows share one annotation weight. The chronological split reserves days 0–44 for query/training opportunities, days 45–51 for selection validation, and days 52–59 as a fixed independent evaluation set. Whole-day and episode boundaries have at least a 300 second purge. Scalers use training labels only. Hyperparameters are fixed in advance; alpha and model selection see validation but never evaluation outcomes.

Two daily query opportunities are four hours apart, each containing three already-ended episodes no older than 30 minutes. Production ActiveQuerySelector runs with all-random selection versus uncertainty/diversity and a 25% random-audit fraction. A simulated oracle answers only the selected episode. Fits use only earlier answered queries. Budgets of 30, 60 and 90 therefore require 15, 30 and 45 days respectively and the same number of automatic overlays for each strategy. Neither method gets extra labels, and both use the same independent evaluation set. The unqueried latent labels remain hidden from selection.

All scores use equal episode weights. Per-class missing support is `null`/NA. Uncalibrated component thresholds are an engineering rejection convention, not confidence probabilities. Precision/recall and confusion matrices report the full evaluation set; accepted-only macro-F1 and accepted/rejected coverage are also stored. No real-data calibration curve is reported because sufficient independent real audit evidence does not exist.

## Parameter simulation

Each seed samples a different hidden simulated growth/recovery pair. Twelve days contain two independently reset work segments per day with a confirmed rest and before/after self-reports. Stochastic self-reports arise from a logistic preference link plus response noise; the last two days add a preference shift. Frozen state components are sampled independently of those reports.

Random Search and TPE each replay exactly the same fitting history 64 times, using the production workload dynamics and fixed regularized objective. Nine complete days fit parameters; three later days are held out. The optimizer winner is selected by fitting loss, not later-days loss. Candidate parameter stability across seeds reflects simulated heterogeneity as well as noise; it is not a measurement of human stability. Budget curves are every trial's `best_so_far` series, not interpolated or invented observations.

## Results and evidence limits

[The results report](../experiments/results/report.md) and its machine-readable per-seed records contain the current rerun's exact metrics. Active selection does not improve every condition, and lower fitting loss does not guarantee lower held-out loss.

These simulator results do not justify activating real personal versions. Future shadow activation, withdrawal, damaged-model fallback, cancellation, causal event ordering and label availability are covered separately by lifecycle tests. System cost and native longevity appear in [platform status](platform-status.md). This experiment does not substitute for a two-hour real desktop run or establish the effectiveness of any reminder policy.
